## 6. Decisions made
All are also in `PROGRESS.md` → Decisions.
- **Login throttle:** `login_throttle` keyed by `HMAC-SHA256(EMAIL_HMAC_SECRET, lowercased email)`; one path for known and unknown emails (same lookups, one Argon2 verify, atomic upsert count, 15-minute lock at 5, same responses); stale rows purged hourly after 24 h. New required secret `EMAIL_HMAC_SECRET`, separate from `CSRF_SECRET`.
- **Migrations:** additive `20261029160836_p2_platform_services`, then `20261029160853_drop_user_lockout_columns` (hand-written, no backfill, see §5).
- **Module discovery:** `loadModules()` imports `modules/<folder>/index.ts` or `index.js`, takes the default export (ESM or CommonJS), validates strictly (folder = id, unique ids and purposes), fails startup with every problem listed. Mounted behind `requireAuth` + `requireRole(...roles)`. Proven for a `{"type":"commonjs"}` folder by a test.
- **Dashboard timeout:** 1.5 s per provider via `AbortSignal.timeout`, raced; output validated against `dashboardSummaryRegistry`; failures logged with request ID and module ID.
- **Password rules:** 12–256 characters, differs from current, no email local part (≥3 chars); temporary passwords 24 base64url characters; forced-change gate allows only me, change-password, logout, login and health; change-password limited to 10 per 15 minutes per user.
- **Last admin:** `SELECT … FOR UPDATE` of all active admins (id order) in the transaction; self-demote/deactivate/reset refused.
- **Audit trigger:** `audit_log_append_only` raises on UPDATE or DELETE; `actor_id` FK RESTRICT; failed logins store only the email HMAC.
- **Multipart and file-type libraries:** `busboy` 1.6 (`defParamCharset: 'utf8'`, limits files 1 / fields 0 / parts 1 / fileSize per purpose) and `file-type` 22 (`fileTypeFromFile`).
- **Storage layout:** `STORAGE_DIR/tmp/<uuid>.part` and `STORAGE_DIR/objects/<uuid>`, mode 0700/0600, outside the repo (checked); `Storage` interface with a disk implementation; quota re-checked under a per-user advisory lock; soft delete + hourly sweep; downloads via `res.sendFile` for Range.
- **OpenAPI library:** `zod-openapi` 6 with Zod 4's native `.meta({ id })`; swagger-ui-express for `/api/docs` (local assets, no CDN), outside production only; `docs/api/openapi.json` committed and Prettier-ignored.
- **Search:** `pg_trgm` GIN indexes on `users.name` and `users.email`, declared in the Prisma schema (no drift); `escapeLike()` because Prisma's `contains` passes `%`/`_` through.
- **Shared helpers:** `platform/paging.ts` (`olderThan`, `toPage`, cursors) used by feed, admin users and audit; `IdParam` in `http.ts`.
- **Risk recorded:** the partial unread index relies on Prisma's `partialIndexes` preview; a test now fails if it disappears.
- **Backend first:** all phases build backend only; frontend in U1–U2.

## 9. Security and performance review
Security
- Validation: every new body, query and param uses a strict Zod schema (`ChangePasswordRequest`, `AdminUserQuery`, `CreateUserRequest`, `UpdateUserRequest`, `AuditQuery`, `IdParam`, `PurposeParam`); module definitions and file purposes are validated strictly at startup; uploads are limited (one file, no fields, size per purpose) and type-checked by content.
- SQL: Prisma only; the new raw statements are tagged templates (`SELECT … FOR UPDATE`, `pg_advisory_xact_lock(hashtext(${id}))`). LIKE wildcards in search are escaped.
- Role and ownership: modules are mounted behind auth + role guard by the platform; admin routes have their own `requireRole('admin')`; files go through each purpose's `authorizeRead` and return 404 to anyone else; delete is owner or admin; admins cannot remove themselves or the last active admin.
- Passwords and sessions: Argon2id unchanged; temporary passwords (144 bits) shown once, stored only as hashes, forced change before any other use; change-password keeps only the current session; deactivate/reset delete every session and close live streams.
- Account enumeration: fixed — known and unknown emails get the same responses and the same lockout; the throttle table and failed-login audit entries hold only an HMAC.
- CSRF: every new unsafe route sits behind the existing token and Origin checks (tested for uploads and change-password).
- Rate limits: login (IP + per email), change-password (per user), uploads (20/min per user) plus a per-user quota.
- Errors: all new errors use `ApiErrorBody`; no stack traces; no passwords, emails of failed logins, temporary passwords or tokens are logged or audited (tested).
- Files: stored outside the repo and every served folder (checked at startup), server-generated keys, `0600` files, `nosniff`, `attachment` with a sanitised name, `private` caching; never served by the static middleware.
- Secrets: `EMAIL_HMAC_SECRET` validated at startup (≥32 bytes); `.env` files still git-ignored; nothing secret committed.
- Audit: append-only enforced by the database, not just by the code.
- `npm audit --omit=dev`: 0 vulnerabilities. Interactive API docs are not served in production.

Performance
- Indexes on every new FK and filter/sort column (§7); EXPLAIN in §8 shows the trigram, list, action and actor indexes in use.
- Every new list (`/api/admin/users`, `/api/admin/audit`) is cursor-paged (default 20, max 100) with the same index-seekable keyset as the feed.
- No N+1: audit actors are one batched include; the dashboard runs its queries and providers in parallel.
- Heavy work stays out of the request path where it matters: uploads stream to disk with constant memory; downloads stream with Range.

Reliability
- Multi-step writes are single transactions (create user + audit, update + session delete + audit, failed login + throttle + audit, upload insert + rename). Uniqueness by constraints (email, storage key).
- Shutdown also stops the file sweep timer.
- Every failure path of an upload deletes its temporary file (tested for oversize, wrong type, quota and client abort).

Not met / deferred: the per-user upload and change-password limiters use the in-memory store (single instance, marked `ponytail:` like P1's); there is no automated test that docs are hidden in production (env is read once per process; checked by hand with `npm start`); screens have no loading/empty/error states because there are no screens (backend first).
