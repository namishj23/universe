## 6. Decisions made
All are also in `PROGRESS.md` → Decisions.
- **Module format:** API is ESM (`type: module`, `module`/`moduleResolution: nodenext`). Prisma 7 is ESM-only. Module B mounts unchanged in P3: its files go under `apps/api/src/modules/rides/` with a nested `{"type":"commonjs"}` `package.json`; the ESM app default-imports the router; its CJS code can `require()` ESM platform modules (Node ≥22.12). Verified with a probe. Rule: no top-level `await` in `apps/api/src`.
- **Versions:** Node `>=22.12 <23 || >=24 <25` (`.nvmrc` 24), TypeScript `~6.0.3`, Prisma `7.10.1`, Zod 4, Express 4.22, React 19.3, React Router 8.5, Vite 8, Vitest 5.
- **TS flags:** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` (kept on: no conflicts), `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`.
- **Contracts from source** via the `@universe/source` export condition (tsc/tsx) and an alias (Vite/Vitest); `dist/` only for `npm start`.
- **Argon2id parameters:** m=19456 KiB, t=2, p=1 (OWASP minimum).
- **Transaction-safe emit:** `transaction((tx, emit) => …)` inserts inside the caller's transaction and pushes only after commit; nothing is pushed on rollback; `emit()` is the one-call shorthand.
- **Timestamps** `timestamptz(3)` for exact cursor round-trips; keyset with a redundant index bound.
- **Partial unread index** via Prisma's `partialIndexes` preview (in the schema, no drift).
- **PostGIS in schema `extensions`** (see §5); P3 needs a `shadowDatabaseUrl` for PostGIS migrations.
- **Login exempt from the CSRF token** (see §5).
- **Single-instance limits:** in-memory rate-limit store and in-process SSE broker; multi-instance needs Redis or `LISTEN/NOTIFY` (marked in code).
- **No dotenv:** `--env-file-if-exists`, `process.loadEnvFile()`, `ENV_FILE` for the Prisma CLI.
- **Two-browser demo:** `http://127.0.0.1:4000` in `WEB_ORIGINS`.
- **Prettier ignores Markdown.**
- **CSP `upgrade-insecure-requests`** only with `COOKIE_SECURE=true`.
- **Temporary web screens** in `apps/web/src/platform/`; P2 builds `apps/web/src/shell/`.

## 9. Security and performance review
Security
- Validation: every body, query and param goes through a strict Zod schema (`LoginRequest`, `PageQuery`, `AnnouncementRequest`, `IdParam`, cursor tuple); unknown fields → 400. Login also requires `application/json` (415).
- SQL: Prisma only; the two raw statements are tagged templates (`SELECT 1`, the test-only truncate block). No `$queryRawUnsafe`.
- Role and ownership: `requireAuth` on every activity route, `requireRole('admin')` on announcements; every activity query is scoped to `recipientId = signed-in user`; others' event IDs return 404.
- Passwords: Argon2id (OWASP minimum); same 401 for wrong email, wrong password and inactive account, with a dummy verify for unknown emails. Sessions: 32 random bytes in an httpOnly, SameSite=Lax cookie, Secure when `COOKIE_SECURE=true`; only SHA-256 stored; rotated on login; deleted on logout, expiry, idleness or a deactivated user.
- CSRF: HMAC token header with a constant-time comparison on every unsafe request with a session, and an Origin allow-list on every unsafe request (login exempt from the token only, see §5).
- Rate limits: login 10/min/IP plus DB lockout. Known limitation: a 429 lockout response appears only for existing accounts, so after five failures an attacker can tell an account exists. Its message is identical to the IP rate-limit message. No uploads in P1.
- Errors: always `ApiErrorBody` with the request ID; 500s return a generic message, and stacks go to logs only. Logs redact `authorization`, `cookie`, `set-cookie`, `x-csrf-token` and `password`; bodies are not logged.
- Secrets: env only, validated at startup (`CSRF_SECRET` ≥32 bytes); `.env` files are git-ignored; secret scan clean; Module B's `backend/.env` was not opened or copied.
- Headers: helmet (CSP, frame-ancestors, nosniff, etc.), `x-powered-by` off, CORS limited to `WEB_ORIGINS` with credentials.
- Audit: `npm audit --omit=dev` 0. `pip-audit`: not applicable (no Python yet).

Performance
- Indexes on every FK (`sessions.user_id`, `activity_events.recipient_id` via the feed index, `actor_id`) and on filter/sort columns (`users.role`, `sessions.expires_at`, feed composite, partial unread); EXPLAIN shown in §8.
- Cursor paging, default 20 / max 100; keyset with an index-seekable bound.
- No N+1: the session and user come from one query; actors load in one batched query; unread counts after a fan-out use one `groupBy`; fan-out inserts go in 1,000-row batches.
- Live updates use SSE (no polling); `last_seen_at` is written at most every 5 minutes.
- Web: `AbortController` on initial loads; the `EventSource` and its listeners are removed on unmount (tested).

Reliability
- Login's multi-step write (reset counters, delete old session, create session) runs in one transaction; activity inserts run in the caller's transaction; email uniqueness is a DB constraint.
- Screens: loading ("Loading…"), empty ("No activity yet.") and error (role=alert) states.
- Shutdown: stops listening, closes SSE streams, stops the cleanup timer, disconnects Prisma, hard exit at 10 s (measured 116 ms).

Not met / deferred: multi-instance scaling (in-memory limiter and broker, documented); the heartbeat runs one session query per open stream every 25 s (fine for a demo, noted).
