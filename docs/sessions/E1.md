## 2. Summary
Person 2's Django code is now a service behind the platform, in `services/exam/`. It runs on Postgres `universe_exam` only, uses `PlatformIdentity` for auth (loopback, HMAC token, identity headers, invigilator/admin), returns one error shape for every error, and has UUID ids. All contract §4 endpoints except live are in place. Review and reopen lock the flag row and write history. Analysis runs in a background thread, one job at a time. Calls to the platform are direct, with 3 tries. This is the minimum scope; the outbox, live webcam and the end-to-end check are deferred.

Uploads stream to a temp file with a 200 MB limit. Lists use cursor paging over composite indexes. Review runs in one transaction with `select_for_update`. ## 12. How to verify by hand
`cd services/exam && scripts/test.sh`. Then run `.venv/bin/waitress-serve --host 127.0.0.1 --port 8000 exam_service.wsgi:application` and `curl -i 127.0.0.1:8000/exam/flags`, which should give 401. The same request with `-H "X-Service-Token: $SERVICE_TOKEN_EXAM" -H "X-UniVerse-User-Id: <uuid>" -H "X-UniVerse-User-Role: invigilator"` should give 200.

E2E (later): sign in on :4200 as the seeded invigilator with a cookie jar and CSRF, then `POST /api/exam/clips` (multipart file + examId) and `GET /api/exam/flags`. Then `POST /api/exam/flags/<id>/review` with `{"decision":"dismiss","note":"..."}` and check the inbox and audit log. A student should get 403.

### For the UI phase
- `GET /api/exam/exams` → `{items:[{id,name,room,label,createdAt}],nextCursor}`
- `POST /api/exam/clips` multipart `file`, `examId`, `zone?` (`x1,y1,x2,y2`) → 202 `{clipId,jobId}`
- `GET /api/exam/clips[?examId]`, `GET /api/exam/clips/:id` → `{id,examId,source,contentType,sizeBytes,durationSeconds,zone,createdAt,uploadedBy,flagCount,videoUrl,job:{id,status: queued|running|completed|failed,progress,error,startedAt,finishedAt}}`
- `GET /api/exam/clips/:id/video` (Range, 206)
- `GET /api/exam/flags?status=open|dismissed|resolved|all&examId&limit&cursor` → `{items,nextCursor,counts:{open,dismissed,resolved}}`. Each item: `{id,clipId,examId,signal,signalLabel,startAt,endAt,confidence,peakConfidence,track:{id,label},seatLabel,status,decision,snapshotUrl,createdAt}`
- `GET /api/exam/flags/:id` adds `{explanation,evidence,bbox,note,decidedBy,decidedAt,history:[{action,decision,fromStatus,toStatus,note,actor,at}]}`
- `GET /api/exam/flags/:id/snapshot` (JPEG)
- `POST /api/exam/flags/:id/review` `{decision:"dismiss"|"follow_up",note}`; `POST /api/exam/flags/:id/reopen` `{note}`. A flag that is not in the right state returns 409 `CONFLICT`.
- `GET /api/exam/dashboard-summary` → `{openFlags,lastProcessedAt}`
