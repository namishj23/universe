## 2. Summary
The web app now has the real platform UI, rebuilt from the team's Claude Design handoff and wired to the real API in light and dark.
- **Screens:** sign-in (demo list behind a flag), forced and voluntary password change, the dashboard "Your week", the inbox, and admin users and audit log.
- **Shell:** a role-aware sidebar from `GET /api/modules` that becomes a top bar below 1024px, and one live activity stream per tab.
- **Errors:** 403, 404, "Something went wrong" and "new version" pages.
- **Module pages** are discovered by folder and lazily loaded.
- **Backend:** `GET /api/dashboard/week` with a `weekItems` provider contract for P6, plus an audit prefix filter.

A Playwright harness renders the prototype and the build side by side. At 1440×900, 78 of 84 cases are under 0.5% different. The other six are data the API doesn't have yet, plus one deliberate choice. At 390px the prototype has no responsive layout, so those numbers are expected differences (approved). 204 visual baselines, a Stylelint token guard, `DESIGN-SYSTEM.md` and 49 web tests lock it in. The phase is complete.

## 6. Decisions made
All are also in `PROGRESS.md` → Decisions.
- Exact replication enforced by `design:compare`, `test:visual` (204 baselines plus Chromium axe), Stylelint and `DESIGN-SYSTEM.md`; the CLAUDE.md rule is added.
- 390px follows the README's responsive rules; comparisons there are expected differences.
- Data layer: TanStack Query 5, retries only network errors and 5xx, signals passed through, cache cleared on sign-out; `mustChangePassword` in auth state with a route gate.
- Live activity: one EventSource per tab in `ActivityProvider`; de-dup by id; unread from the stream; `subscribe()` for ephemeral events; a single-flight `/me` check, otherwise a 1 s → 30 s backoff.
- Components: Radix primitives styled only with tokens; focus returns to the opener.
- Theme storage: `data-theme` on `<html>`, system default, `localStorage` `uv-theme` override in try/catch; fonts self-hosted.
- Demo flag `VITE_DEMO_MODE` (email only). Login error wording by status.
- Week endpoint contract: `{ from, timeZone, days[7], modules }`, items `{ module, time | allDay, title, status?: { label, tone }, confirmed, href }`; provider items `{ at, allDay?, title, status?, confirmed, href }`, max 50, 1.5 s each.
- Audit `actionPrefix`.
- Web module discovery by folder (`module.ts` eager, `Page.tsx` lazy); 403 for unlisted modules; placeholder for listed modules without a folder.
- Inbox wording rule: lower case follows the actor; capitalised stands alone; fallback to `payload.message`, then the type.
- Admin extras: the Manage user modal, the `driver` filter, the announcement card kept on an empty inbox.
- Ports for a second copy through `apps/web/.env.local`.

## 9. Security and performance review
- **Validation:**
  - `GET /api/dashboard/week` parses query (`WeekQuery.strict()`) and the `X-Timezone` header (IANA check, ≤64 chars) with Zod; unknown fields → 400.
  - Provider output is parsed (`WeekProviderOutput`, ≤50 items; `href` must be an internal path, not `//host`).
  - `actionPrefix` is `^[a-z]+$`, ≤30.
  - The web parses every API response with the contracts' schemas; the SSE payloads with `safeParse`.
- **SQL:** Prisma only (`startsWith`); no raw SQL added.
- **Role and ownership:**
  - The week endpoint runs only `visibleModules(modules, user.role)`, so a module the role can't see contributes nothing (tested).
  - Admin routes stay admin-only on the server; the web's 403 page and hidden Admin nav are cosmetic on top of that.
  - The web never switches roles; the role comes from the session.
- **Sessions and secrets:**
  - The CSRF token stays in memory (never `localStorage`); `localStorage` holds only the theme.
  - The query cache is cleared on sign-out, so the next user never sees the last one's data.
  - Temporary passwords are shown once and dropped from memory when the modal closes (tested).
  - The demo list never shows or fills a password.
- **Output:** activity text is rendered as React text, never HTML; links come only from contract-checked internal paths.
- **CSP:** fonts self-hosted; no inline scripts; no third-party requests from the app (checked in the built app).
- **Errors:** the web shows the API's `requestId` and never a stack. The login message is the same for a wrong email and a wrong password.
- **Performance:**
  - No polling; one EventSource per tab (tested); live events go into the cache, not refetches.
  - Search is debounced 250 ms with `keepPreviousData`; every request is cancellable through the query `signal`.
  - Lists use cursor paging with "Load more" / "Load older".
  - Module pages are separate lazy chunks.
  - The week endpoint runs providers in parallel, 1.5 s each.
- **Reliability:**
  - Every screen has loading, empty and error states.
  - A failed module summary or week provider never fails the page.
  - Errors are caught at page and app level, with a "new version" path for failed chunks.
  - Timers, listeners, the EventSource and media-query listeners are cleaned up on unmount.
- **Accessibility:** focus ring, skip link, `aria-current`, focus to the h1 and to the login alert, focus trap and return in dialogs, labels as names, axe clean in jsdom and Chromium.
- **Not met / noted:**
  - Three design-level contrast cases are kept exact and raised with the design team.
  - The initial chunk is 589 kB (176 kB gzip): React, React Router, TanStack Query, Radix and Zod with the contracts. Lazy-loading the admin screen or the contracts' rides schemas would cut it; not done (not required, measured).
  - Visual baselines are macOS-specific.
