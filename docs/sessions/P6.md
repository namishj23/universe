## 2. Summary
The five modules now work as one platform for Person 1's scope. Modules reach each other only through `platform.modules.get(id)`: read-only, validated both ways, limited to 500 ms, scoped to the signed-in user, and harmless when a module is missing. The seed now tells the design's story across all modules, `npm run demo:reset` restarts it from now, and a storyline test runs the live demo through the API with live SSE checks. `main` and U1 are merged. ## 9. Security and performance review
- **Validation:** every new input is a strict Zod schema (`arriveBy` exclusive with `pickupTime`; public API inputs strict, with `actor` stripped to `{ id, role }`). Outputs crossing modules are parsed too, so a module can't leak extra fields.
- **Access:**
  - every route has `requireAuth` (except login and health) and role metadata, enforced by a test and published in `docs/ROLES.md`;
  - public API providers scope by `actor`: `upcomingForUser` only the actor's rides, `sessionsForUser` only the actor's sessions;
  - `studyMinutesThisWeek` is null for anyone but the owner with sharing on (mentors and admins get null; tested).
- **Privacy:** the hub never sees wellbeing data except one opt-in number; mentors never see it. Wellbeing writes no audit entries; the storyline checks the audit log has nothing from wellbeing. Week items reveal nothing to other users (they are per user).
- **SQL:** Prisma and tagged `$queryRaw` only; demo:reset deletes through Prisma delegates (no dynamic SQL).
- **Destructive operations:** `demo:reset` is local-only (host check), pairs `NODE_ENV` with the database name, prints first and needs `--yes`. It never touches users, sessions or the append-only audit log.
- **Failure isolation:** a cross-module call is time-limited (500 ms) and fails closed (503) or is dropped where the data is optional. Week providers keep U1's 1.5 s per-module isolation; tested with a failing provider and a missing module.
- **Performance:** new queries use indexes (EXPLAIN above); no N+1 (ride links look up distinct stops in parallel against the in-memory graph cache; week providers are one query per kind). Lists stay paged. Live updates use the existing SSE broker.
- **Honesty:** savings and `arriveBy` times are labelled estimates; the README table lists the simulated parts (payments, driver ETA, browsing events from sample files; energy figures are estimates).
- **Not met / open:** the platform-wide time-zone shift (HIGH, P5's finding) is still open for P8; raw SQL views of timestamps are shifted by +05:30, while the API is consistent. The single-instance limits (rate limiters, SSE broker, idempotency map) are unchanged.
