## 6. Decisions made
All of them are in `PROGRESS.md` under "Decisions" (U2) and "Open questions" (decided … U2). The main ones:
- Rides is the student/mentor portal only (user).
- Shared widgets and the `--fs-36`/`--fs-28` tokens; `invalidates` for live updates; FormData in `request()`.

## 9. Security and performance review
- Validation: every response is parsed with the contracts' Zod schemas. Request bodies are built from typed contract inputs, and the server still validates them.
- No `dangerouslySetInnerHTML`. User text (notes, chat, names) is rendered as text. Links are internal only, and downloads go through `/api/files/:id`. Client file checks (2 MB JSON, upload type) are only a courtesy; the server decides.
- CSRF header on every unsafe request, FormData uploads included. Nothing sensitive is in `localStorage`.
- Wellbeing:
  - only totals rows and settings reach the server (tested);
  - raw events, rules and sessions stay in IndexedDB, per user;
  - queries use `gcTime: 0` and are cleared on sign-out (tested);
  - nothing raw goes into query keys or URLs;
  - totals are uploaded only while tracking collects.
- CSP: the `eval` violation is fixed, with no relaxation of the policy.
- Performance:
  - each module is its own lazy chunk, 10–13 kB gzip;
  - every list uses cursor "Load more";
  - search is debounced and every query passes its `signal`;
  - the stop graph lays out once per graph;
  - the focus timer runs only while the page is visible and is cleared on unmount;
  - live updates come only through the one EventSource (`invalidates`), with no polling.
- Not met: the axe audit, the full design matrix and baselines for the new screens are U3's. The rides `GET /carpool/driver` 404 for non-drivers is a normal API state that the browser logs (backend gap below).
